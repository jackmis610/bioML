# bioML

Predicting what a metabolic cart measures — **VO2, RER, and fat/carbohydrate oxidation** — from what a consumer wearable records: PPG heart rate, an optional power meter, an optional CGM, and intake-form context.

The project pairs a physiology-grounded synthetic CPET generator (every parameter cited) with a multitask LightGBM model, a reproducible evaluation harness with two baselines, and a FastAPI inference service that builds its features through the same code path as the trainer. The synthetic phase ships standalone; the schema is designed so real CPET + wearable data (Aevox partnership, phase 2) drops in as a one-file loader swap.

**Read next:** [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) is the full walk-through (layers, decisions, limitations). [`reports/v2/REPORT.md`](reports/v2/REPORT.md) is the complete evaluation.

## Headline results

<!-- BEGIN:headline -->
| Model | RER MAE | VO2 MAE (mL/min) | LT2 AUC | LT2 Brier | fat-ox MAE (g/min) |
|---|---|---|---|---|---|
| HR-zone coaching heuristic | 0.0498 | 472 | 0.701 | 0.1152 | 0.186 |
| Population-mean curve | 0.0418 | 313 | 0.883 | 0.0875 | 0.071 |
| **LightGBM multitask v2** | **0.0346** | **113** | **0.959** | **0.0678** | **0.069** |

Relative to the population curve: RER MAE -17%, VO2 MAE -64%, LT2 Brier -23%, fat-ox MAE -2%. Relative to the HR-zone heuristic: RER MAE -31%, VO2 MAE -76%.

*5-fold subject-wise CV, n = 100 synthetic subjects (75,830 one-second rows), seed 42, 400 boosting rounds, 27 wearable-only features. Generated by `make report` (2026-11-05, bioml 0.2.0).*
<!-- END:headline -->

Predictions use **wearable-only inputs**. Lab signals exist only as training labels and evaluation references, and a test fails if any reach the feature matrix. RER error sits near a floor set by latent diet state (which no wearable but a CGM can see), so fat-oxidation error in the Frayn-valid range is close to the population curve's; the model's gains are VO2, the gate's precision (0.96 vs 0.90), and carbohydrate oxidation (MAE halved).

Fat oxidation is emitted only where the Frayn stoichiometry is valid (`rer_pred < 0.99 AND P[above LT2] < 0.5`); otherwise the API returns `regime = "buffering_dominated"` and nulls rather than a confidently wrong number. The report scores that gate as a classifier.

## How it fits together

```
research/spec.yaml ──► generator ──► data/synthetic/v1 (subjects · sessions · samples, Parquet)
                        (subject priors → ramp CPET → per-second VO2/RER/HR/glycogen → PPG/power/CGM noise)
                                                │
                                                ▼
                               eval/features.py  build_features()   ◄──── serve/pipeline.py (same call)
                               27 wearable-only features · 8 groups · causal windows
                                                │
                              ┌─────────────────┼──────────────────┐
                              ▼                 ▼                  ▼
                        train.py           eval/report.py      serve/app.py
                   3 × LightGBM +       baselines on same     POST /predict
                   metadata.json        folds · calibration   → inference.py gate
                                        · SHAP · ablations    → fat/CHO/kcal or abstain
```

## Quick start

```bash
make install          # uv sync --extra ml --extra serve --extra dev   (Python 3.12 via .python-version)
make data             # 100 synthetic subjects, seed 42 → data/synthetic/v1   (~3 s)
make train            # 5-fold subject-wise CV, then save models/v2 with metadata.json
make report           # baselines, calibration, SHAP, 6 ablations → reports/v2   (~7 min)
make serve            # FastAPI on http://127.0.0.1:8000  (docs at /docs)
make demo             # Streamlit: truth vs prediction for any synthetic subject
make check            # ruff + mypy --strict + pytest (136 tests)
```

Without `make`:

```bash
uv run python -m bioml generate --n-subjects 100 --seed 42 --out data/synthetic/v1
uv run python -m bioml train --data data/synthetic/v1 --k 5 --n-estimators 400 --save-model models/v2
uv run python -m bioml evaluate --data data/synthetic/v1 --out reports/v2
uv run python -m bioml serve --model models/v2 --port 8000
```

## The API

```bash
curl -s localhost:8000/health
# {"status":"ok","model_path":"models/v2","model_version":"...","bioml_version":"0.2.0","n_features":27}

curl -s localhost:8000/predict -H 'content-type: application/json' -d '{
  "subject": {"age_years": 34, "sex": "M", "height_cm": 181, "weight_kg": 74,
              "vo2max_estimated_wearable_mlkgmin": 58},
  "session": {"ambient_temp_c": 21},
  "samples": [
    {"t_s": 0,   "hr_wearable_bpm": 71,  "power_wearable_w": 50},
    {"t_s": 1,   "hr_wearable_bpm": 72,  "power_wearable_w": 50},
    {"t_s": 2,   "hr_wearable_bpm": null, "power_wearable_w": 51}
  ]
}'
```

The response carries one row per requested second (`rer_pred`, `vo2_pred_mlmin`, `lt2_prob`, `regime`, `fat_ox_pred_g_per_min`, …), a session summary including the **HR and power at peak predicted fat oxidation** (a wearable-only Fatmax estimate), the gate policy used, and an `imputed` map naming any intake fields (fat-free mass, resting HR, training status) that were filled from population priors because the caller omitted them. Timestamps may have gaps; the service reindexes to a 1 Hz grid so rolling features keep their meaning. Out-of-range inputs are rejected with 422. A 10-minute session scores in about 28 ms on a laptop.

`GET /model/info` returns the loaded artifact's `metadata.json`: feature contract, hyperparameters, data provenance, CV metrics, package versions, git SHA.

## What's encoded

Every choice in the generator and model is anchored to the literature. The `research/` directory is the source of truth:

- **`research/physiology_priors.md`** — metabolic-physiology priors with citations (Frayn 1983 substrate equations, Tanaka 2001 HRmax, Maunder 2018 MFO norms, Coyle 1986 glycogen depletion, Romijn 1993 substrate kinetics, Iannetta threshold cohort).
- **`research/sensor_noise.md`** — wearable validation studies (Gillinov 2017 PPG, Garg 2022 Dexcom G7, Lillo-Bevia 2021 power meters) → per-device noise / dropout / lag spec.
- **`research/design_decisions.md`** — the load-bearing calls: (D1) wide, correlated threshold priors; (D2) 4-segment RER curve with a Fatmax knee; (D3) biphasic glycogen depletion; (D4) direct RER prediction with an auxiliary LT2 head and downstream Frayn gating; (D5) squared-error VO2 objective after Huber clipping was shown to starve the tails.
- **`research/schema_design.md`** — the three-table contract, negotiated against the real-data use case before any code.
- **`research/spec.yaml`** — the operational parameter file consumed by the generator and by the service's intake imputation.


## Status

**Phase 1, synthetic scaffold: complete, v2.** Generator, model, evaluation, and service all run end to end under CI (ruff, mypy strict, pytest, and a generate → train → evaluate smoke). Dataset regenerates from a seed; model carries its contract; docs tables are generated from the report.

**Phase 2, real CPET data: pending.** Schema and loader boundary are designed; see `docs/ARCHITECTURE.md` §13 for the validation plan (sim-to-real gap by stratum, synthetic → real transfer, measured sensor priors).

**Known limitations** (details in `docs/ARCHITECTURE.md` §14): one protocol (ramp) so the session clock is a shortcut; the model has learned the generator until real data arrives; n = 100 by choice; serving has no auth, logging, or drift monitoring yet.
